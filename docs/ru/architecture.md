# Архитектура

```text
React UI → PythonRunner → dedicated Web Worker → Pyodide / Python
    │             │                                  │
    │             └── structured ExecutionResult ← JSON
    └── versioned localStorage

FastAPI → dist/ + /api/health + /api/curriculum
Future TutorProvider → server adapter → local or cloud LLM
```

## Модули

- `src/content/*.md`: независимая теория на русском, English technical terms.
- `src/content/index.ts`: каталог уроков, примеры, типичные ошибки, roadmap.
- `src/content/exercises.json`: декларативные задания и открытые тесты.
- `src/content/solutions.json`: отдельные эталоны, не импортируются в UI.
- `src/engine/harness.ts`: формирует Python-программу проверки из JSON.
- `src/engine/runner.ts`: создание, загрузка, дедлайн, завершение Worker.
- `public/python-worker.js`: загрузка локального Pyodide и выполнение harness.
- `src/engine/progress.ts`: версия хранилища и запись попыток.
- `src/tutor/provider.ts`: контракт будущего server-backed наставника.
- `backend/main.py`: необязательный host и API метаданных.

## Запуск и проверки

Каждый запуск создаёт **новый Worker**, поэтому переменные, импорты и модификации предыдущего запуска не переносятся. Время загрузки Python ограничено 60 секундами, выполнение — 5 секундами на весь набор тестов. Главный поток прекращает Worker через terminate(), даже если Python заблокирован бесконечным циклом. Пользователь может остановить выполнение раньше. При редактировании кода, смене задания или страницы старый запуск отменяется; запоздалые результаты не записываются в новое задание.

Run исполняет код один раз. Check для каждого теста разбирает исходный код через ast, подменяет **первое верхнеуровневое присваивание** каждой объявленной входной переменной и запускает программу в новом namespace. Затем вычисляет выражение теста и сравнивает с ожидаемым значением Python. Поэтому нельзя заменять алгоритм константой, рассчитанной только для исходного примера. Это договорённость текущего вида задач — не универсальный runner для произвольных Python-проектов.

Для функций, файлов, async/API и проектов следует добавлять отдельные виды harness, сохраняя контракт ExecutionResult. Серверный runner не должен использовать exec() в основном FastAPI-процессе: ему нужен отдельный контейнер/процесс с OS-изоляцией, квотами CPU/RAM, read-only FS, ограничениями сети и уничтожением после выполнения.

Вывод ограничен 20 000 символов на stdout/stderr, traceback и значения также обрезаются. Это ограничение интерфейса; отдельная квота оперативной памяти не реализована. Нельзя считать Web Worker защитой от всех способов исчерпания памяти браузера.

## Граница доверия

Решение считается правильным по тестам, без LLM. Но браузер полностью контролируется учеником: тесты, прогресс и сообщения Worker можно изменить через DevTools. Это учебная локальная проверка, **не защищённая аттестация**. У Pyodide есть JS interop; Worker изолирует выполнение от DOM главной страницы, но не является границей безопасности для секретов, сети и origin. Не размещай на этом origin секретные API или привилегированные endpoints.

Эталоны отделены от starter code и не отправляются в основной JS bundle, но в исходном репозитории они открыты. Скрытые тесты и достоверная сертификация потребуют защищённого backend-runner и серверного учёта результатов.

## AI и публикация новых задач

TutorProvider задаёт explain_error, give_hint, explain_concept, generate_similar_exercise, review_solution. Реальный провайдер ещё не реализован. API возвращает 501, а не фиктивные ответы модели. Будущий адаптер хранит ключи на сервере, ограничивает размер запросов и доступ, не передаёт модели право выставлять pass.

`ValidatedExercise` описывает результат будущей проверки, а `canPublish` проверяет форму отчёта. Это **не выполняющий валидацию pipeline** и не доказательство безопасности. До подключения генерации сервер обязан самостоятельно запускать эталон и тесты, проверять однозначность задания и версионировать опубликованный контент.
