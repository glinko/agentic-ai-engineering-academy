# Как добавить контент

1. Создай `src/content/<lesson_id>.md` с краткой теорией, English terms и распространёнными ошибками.
2. В `src/content/ru.ts` и `src/content/en/index.ts` добавь Lesson: id, title, subtitle, minutes, theory, три исполняемых examples и mistakes. Английская теория и задания хранятся в `src/content/en/`. Идентификаторы и контракты тестов должны совпадать между языками.
3. Добавь три задания в `exercises.json` и отдельные эталоны в `solutions.json`.
4. Выполни `pnpm test`, `pnpm test:content`, `pnpm build`. Для изменений движка или UI — также `pnpm test:e2e`.

## Формат задания

```json
{
  "id": "unique-id",
  "lesson_id": "variables",
  "title": "Сумма токенов",
  "difficulty": "Intermediate",
  "learning_objectives": ["Преобразовывать строки в числа"],
  "theory": "variables",
  "description": "Вычисли total из input_tokens и output_tokens.",
  "starter_code": "input_tokens = '12'\noutput_tokens = '8'\ntotal = 0\nprint(total)",
  "public_tests": [
    {"name": "Другие значения", "setup": "input_tokens = '7'\noutput_tokens = '3'", "expression": "total", "expected": 10}
  ],
  "hints": ["Подсказка 1", "Подсказка 2", "Подсказка 3"],
  "explanation": "Преобразуй каждую строку через int() перед сложением.",
  "estimated_minutes": 15
}
```

`theory` — ссылка на id теории; полный текст хранится в Markdown. `reference_solution` намеренно отделён: `solutions.json` содержит отображение `id → Python code`. При необходимости получить единую сущность для авторского инструмента объедини их по id; не включай эталоны в стартовый код или основной клиентский bundle.

У difficulty допустимы стабильные значения Beginner, Intermediate, Checkpoint; интерфейс переводит их подписи. Для обычных заданий нужны три ступени подсказок; для контрольных hints пустой и UI не предлагает помощь. Разбор показывается после успешной проверки. После трёх обязательных заданий, включая контрольную, открывается следующий урок.

## Контракт входов и тестов

Входная переменная объявляется отдельным присваиванием на верхнем уровне **до вычислений**. `setup` содержит только присваивания входов. Нельзя использовать chained assignment и объединять входы с выходными значениями. Проверка сохраняет весь алгоритм и заменяет первый присваиваемый input для каждого теста. Объявления входных переменных нужно сохранить в ученическом коде; при удалении runner покажет объяснение.

`expression` вычисляется после выполнения программы в том же namespace. `expected` — JSON-совместимые значения: строки, числа, bool, массивы и объекты. Для bool, когда важен тип, используй `value is True`. Для int — `[value, type(value).__name__]`. Для float нужно задавать проверку с допуском в expression, а не полагаться на точное двоичное равенство.

У каждого задания минимум три воспроизводимых случая, включая пустые данные и границы, где они применимы. Не используй сеть, случайные значения или текущее время. Тестируй не только эталон, но и характерный неверный алгоритм. Смена контракта существующего задания требует нового id или миграции прогресса — иначе старый pass останется действительным.
